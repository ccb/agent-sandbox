# Furniture Seat Spots as a Committed Artifact — tmj-aware, single-source (#537 follow-up)

**Issue:** #537 (PR #544 iteration) · **Branch:** `feat/furniture-spots-537`
(this PR) · **Review track:** godot-ga-main.

**Supersedes** the "No third artifact: `build_penn_world` derives spots at
load" decision in `2026-07-13-furniture-destinations.md` §2. That decision
put the spot rule in two places (WorldMap's runtime derivation + the
generator's `spots()` for the overlay) and, because the runtime side sees
only the committed matrices, made two defects unfixable at load:

- **Spots inside walls (issue 1):** 33 spots land on `wall`-category tiles
  drawn on Williams' `williams_floor` layer, collision-unsealed. No committed
  matrix distinguishes them from real floor (same collision `0`, same arena
  `1032`) — the wall identity lives only in the tmj, which WorldMap never
  reads.
- **Cross-arena attribution (review #1):** 227 spots (120 in Van Pelt lobby,
  20 in Meyerson lobby, …) are attributed to the spot tile's own arena while
  their adjacent furniture belongs to a neighboring room — a "lobby" spot
  facing another room's bookshelf through a doorway.
- **Parity drift (review #4):** the overlay's spots and the sim's spots are
  two independent implementations, verified equal once by hand (5,586/0) but
  pinned by no test.

## Goal

Compute seat spots **once**, in the generator (which has the tmj + catalog),
excluding wall/window/door cells and requiring same-arena furniture; write
them as a committed artifact; have WorldMap **load** it and the `--debug-
overlay` read the same computed list. One source of truth: the overlay is
what agents do, by construction.

## Current state (verified)

- `gen_furniture_matrix.py` emits `furniture_maze.csv` +
  `furniture_blocks.csv`, and (with `--debug-overlay`) computes spots via
  `spots(furn, collision, W, H)` for the overlay only. It already loads the
  tmj, `furniture_catalog.json`, `arena_maze`, `sector_maze`, `collision` in
  `main()`, and builds a gid→category map (`excluded_gids` uses it).
- `WorldMap.__init__` (`backend/world_map.py:99-132`) re-derives
  `furniture_spots: dict[address -> list[(x,y)]]` from `furniture_maze` +
  `collision` + `arena_m`/`sector_m`, keyed `f"{world}:{sector}:{arena}"`.
  The just-landed fix already made both copies "floor beside furniture, not
  the furniture tile" (issue 2) — that rule stays; this moves *where* it runs.
- `_pin_building_meeting_points` reads `world_map.furniture_spots[address]`
  — unchanged by this spec.
- `special_blocks/*.csv` are `, `-separated (`id, world, sector, arena,
  name`); building/room names carry no commas. `WorldMap` reads them with
  `_id_to_label`/`_read_rows` and flat mazes with `_read_flat`.

## Design

### 1. The generator computes and writes spots

New `spots(...)` signature in `gen_furniture_matrix.py` takes the arena maze
and a structural-cell mask; it returns `(x, y, arena_id)` triples. A cell is
a spot iff:
- `collision[idx] == "0"` (walkable) **and** `furn[idx] == "0"` (not the
  furniture tile itself — issue 2), **and**
- it is **not** structural — no `wall`/`window`/`door`-category tile is drawn
  on it in any tmj layer (issue 1; the mask is built from the tmj + catalog
  the same way `excluded_gids` is), **and**
- it is 4-adjacent to a furniture cell **whose arena equals the spot cell's
  own arena** (review #1 — a lobby spot must border the lobby's own
  furniture, not a neighbor room's through a doorway).

Attribution: the spot's own arena (now guaranteed to match its furniture's).
`main()` writes `special_blocks/furniture_spots.csv`, rows
`world, sector, arena, x, y` (`, `-separated, mirroring the blocks files),
row-major. The `--debug-overlay` consumes the same returned triples, so the
overlay's points are exactly the committed spots.

### 2. WorldMap loads instead of derives

`WorldMap.__init__` replaces the derivation loop (`_beside_furniture` + the
double scan) with a read of `special_blocks/furniture_spots.csv` when
present: for each row, `self.furniture_spots.setdefault(f"{world}:{s}:{a}",
[]).append((x, y))`. The file is **optional** (a world without it — every
non-Penn map — gets `{}`, exactly as today). No tmj, no collision re-scan at
load: the artifact is authoritative. `furniture_maze.csv` stays loaded only
for its existing validation (cell-count check); nothing else in WorldMap
changes.

### 3. Determinism, drift, docs

- The artifact is committed and byte-reproducible (row-major, deterministic
  piece/arena order). Regenerated by the existing `gen_furniture_matrix.py`
  run — no new CLI step.
- Drift gate: still a follow-up (the designed `validate_tmj` extension will
  cover furniture_maze/blocks/spots together). Noted, not built here.
- README already lists the `gen_furniture_matrix.py` regen step; add
  `furniture_spots.csv` to the artifacts it names, and add the missing
  `block_furniture.py` predecessor step (the review's confirmed README gap —
  the spots rule depends on sealed collision).
- `backend/README.md`: note `furniture_spots.csv` alongside the other
  matrix artifacts.

### 4. Out of scope

- Williams' unsealed interior walls in *collision* (agents can path through
  them) — that's the root pathfinding bug, tracked on #538; this spec only
  stops spots from landing there.
- The `_pin_building_meeting_points` routing math, k=4, round-robin — the
  earlier review's cleanup items, not this change.
- A sit-on-the-seat destination (#446).

## Verification

- **Generator unit tests** (`tools/geo/test_furniture_matrix.py`):
  synthetic tmj where (a) a wall tile drawn on a floor layer beside furniture
  is NOT emitted as a spot; (b) a floor cell adjacent only to furniture in a
  *different* arena is NOT emitted for either arena; (c) same-arena adjacency
  IS emitted; (d) the furniture tile itself is not a spot; (e) the csv round-
  trips (write → read → same triples). Idempotent re-run byte-identical.
- **Real-map assertions**: 0 spots on wall/window/door-category cells (was
  33); 0 spots whose adjacent furniture is all foreign-arena (was 227);
  furnished arenas agents visit (Houston lobby, Van Pelt rooms) still have
  spots; the 10 furniture-less lobbies correctly have none (routing falls
  back to centroid, as Williams already does).
- **Backend** (`tests/test_furniture_spots.py`): WorldMap loads the artifact
  (spots present for a furnished arena, `{}` when the file is absent);
  `_pin_building_meeting_points` routing prefers a spot; the byte-identity
  `test_stepper_matches_simulate_prefix` stays green.
- **Parity by construction**: WorldMap's spots == the committed csv == the
  overlay's points — one source, so a dedicated cross-check test is no longer
  needed (the artifact IS the shared definition). One test asserts WorldMap's
  loaded set equals the csv rows.
- `uv run pytest godot-generative-agents/tests/ -q` and
  `godot-generative-agents/tools/geo/test_furniture_matrix.py` green;
  `uv run black .` clean.
- **User visual pass**: regenerate `--debug-overlay`, open in Tiled — no
  spot points on walls, none flooding rugs/sofas, none at foreign-room
  thresholds.
